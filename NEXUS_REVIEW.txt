BUILDING ON A CLEAN WINDOWS X64 MACHINE

1. Install 64-bit Python 3.14 with Tcl/Tk. Open PowerShell in this repository's
   root (the folder containing scripts, tests, release and LICENSE). Confirm
   the selected interpreter is Python 3.14 and 64 bit:

   python -c "import sys,struct,tkinter; print(sys.version); assert sys.version_info[:2] == (3,14); assert struct.calcsize('P') == 8"

2. Download the pinned official runtime. The JSON file contains its exact
   version, Python.org URL, SHA256 and expected signer:

   New-Item -ItemType Directory -Force .cache/runtime-public-beta2 | Out-Null
   $runtimeLock = Get-Content release/python-runtime.json -Raw | ConvertFrom-Json
   Invoke-WebRequest -Uri $runtimeLock.url -OutFile .cache/runtime-public-beta2/python-3.14.0-amd64.zip
   if ((Get-FileHash .cache/runtime-public-beta2/python-3.14.0-amd64.zip -Algorithm SHA256).Hash.ToLowerInvariant() -ne $runtimeLock.sha256) { throw 'Runtime hash mismatch' }

3. Run the tests. Continue only if they pass:

   python -B -m unittest discover -s tests -p 'test_*.py'
   if ($LASTEXITCODE -ne 0) { throw 'Tests failed' }

   Matching source validation ran 813 tests, with 8 optional Unicorn emulator
   tests skipped in the bundled standard-library-only runtime. Unicorn is not
   needed to build or use the release. No game is required for these tests.

4. Build and scan:

   python -B scripts/build_release.py --runtime-archive .cache/runtime-public-beta2/python-3.14.0-amd64.zip
   if ($LASTEXITCODE -ne 0) { throw 'Build or scan failed' }

   Microsoft Defender must be available in Normal mode with antivirus and
   real-time protection enabled. The scan parser expects supported English
   completion output. Unconfirmed output, disabled protection or a detection
   stops the build. No exception/exclusion is created.

5. The completed files are in dist/. latest-build.json identifies the Windows
   and source ZIPs, hashes and scan receipt. Extract the Windows ZIP and open
   Start Dungeons II Camera Mod.cmd. The packaged offline self-tests construct
   the Helper UI without opening the game. Gameplay requires a supported game
   build, as described in release/README.txt.

See release/BUILDING.md for the full packaging and verification design.
The builder refuses to overwrite an existing versioned release artifact.
For another build, use a fresh working copy/build directory. A rebuild records
new timestamps, scan results and metadata, so ZIP hashes need not be identical.
Compare source and pinned retained runtime contents when reviewing provenance.

IMPLEMENTATION AND RUNTIME

The mod implementation is readable Python. There is no separately compiled
mod DLL or executable to reconstruct. The official Python/Tk runtime is the
third-party executable dependency, pinned in release/python-runtime.json.
Retained runtime files are not patched; unused pip/ensurepip are omitted with
an explicit hash manifest. The small existing app icon is generated by
scripts/build_release.py. The later promotional logo is not in this package.

The Helper writes game data for supported camera/control and local visibility
features after executable/build checks. It does not modify game files, saves
or DRM. The native-code patch experiments remain disabled in build_info.py.
The application does not automatically download code or send telemetry.
Optional support/download buttons open the configured Patreon page in the
user's browser only when clicked. Development builds explicitly download the
official runtime as shown above.
